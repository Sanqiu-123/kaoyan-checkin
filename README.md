# 人工智能专业考研每日打卡与进度管理网站

一个本地浏览器可用的考研每日打卡 MVP，面向人工智能专业考研一轮复习。项目使用 React、TypeScript、Vite、Tailwind CSS、shadcn/ui 风格本地组件、Recharts、lucide-react 和可选 Supabase 云同步开发。数据默认保存在浏览器 `IndexedDB` 中，并支持 JSON 备份导出/导入和 PWA 手机安装。

## 已实现功能

- 首页 Dashboard：今日任务、完成率、倒计时、最近 7 天趋势、各科学习时长、总体进度、昨日总结与建议。
- 今日学习策略：首页会根据昨日完成率、目标差距、到期薄弱点和连续低完成情况，生成当天优先级、时间取舍和防偏提醒。
- 教材级计划：内置张宇30讲、王道408章节、英语基础/阅读阶段档案，首页和进度页会显示当前教材焦点、练习闭环和检查点。
- 每日打卡：自动生成每日任务，支持勾选、改时间、改任务、填时长、选质量、写备注、增删任务。
- 补打卡：每日打卡页支持切换日期，补录昨天或任意一天的完成情况，并重新生成当天建议和薄弱点。
- 历史记录：按日期查看历史任务、完成率、学习时长和总结。
- 进度管理：维护数学一、408、英语一的一轮复习进度。
- 薄弱点库：从未完成任务、单项备注和今日总结中自动沉淀薄弱点，支持复盘、标记掌握和手动新增。
- 统计分析：最近 7 天完成率折线图、各科学习时长柱状图、任务完成情况。
- 本周诊断：自动生成本周学习时长、平均完成率、最稳定科目、最薄弱科目和下周建议。
- 目标差距看板：首页显示数学、408、英语距离 7 月 1 日一轮目标的剩余量、所需速度和近 7 天速度。
- 自动复盘任务：如果有到期薄弱点，新生成的当天任务会自动加入“薄弱点复盘”任务。
- 设置：目标日期、每日学习时间、深色模式、备份导出/导入、清空数据二次确认。
- PWA：部署到 HTTPS 后，可以在手机浏览器中“添加到主屏幕”，像 App 一样打开。
- 可选云同步：配置 Supabase 后支持账号登录、上传本地到云端、从云端拉取和自动同步。
- 自动调整建议：保存打卡后，根据各科完成情况生成第二天学习建议；第二天任务生成时会参考前几天打卡结果。

## 安装依赖

```bash
npm install
```

## 本地运行

Windows 用户可以直接双击项目根目录下的：

```text
一键启动.bat
```

脚本会自动安装缺失依赖、启动本地网站并打开浏览器。它会额外打开一个 `Kaoyan Checkin Service` 服务窗口，使用网站期间不要关闭这个服务窗口。若启动失败，请查看项目根目录下的 `startup-log.txt`。

也可以手动运行：

```bash
npm run dev
```

启动后打开终端输出的本地地址，通常是：

```text
http://localhost:5173
```

## 构建

```bash
npm run build
```

## 使用说明

1. 第一次打开网站时，系统会用你的当前复习背景初始化默认进度。
2. 每天第一次打开时，如果当天还没有记录，会根据阶段计划、教材焦点和历史完成情况自动生成当天任务。
3. 每天先看首页“今日学习策略”和“今日教材焦点”，确认今天推进哪一讲/哪一章、练哪类题、检查哪些卡点。
4. 在“每日打卡”页勾选完成情况，填写实际时长、质量与备注后，点击“保存今日打卡”。
5. 保存后会生成一段具体学习建议，并自动把未完成任务、任务备注、今日总结沉淀到“薄弱点库”。
6. 在“薄弱点”页每天处理到期复盘项，复盘一次后系统会自动推迟下次复盘日期，真正掌握后标记为“已掌握”。
7. 在“首页”查看目标差距看板，重点关注“偏慢”和“停滞”的科目。
8. 在“统计分析”页查看本周诊断，判断本周最拖后的科目和下周补救方向。
9. 在“进度管理”页可以手动修正当前讲数、408 章节、英语阅读篇数等长期进度。
10. 所有数据保存在当前浏览器的 `IndexedDB` 中。旧版 `localStorage` 数据会在第一次打开时自动迁移。
11. 在“设置”页可以导出 JSON 备份，也可以从备份文件导入恢复。建议把备份文件放到本地磁盘和网盘中各留一份。
12. 如果配置了 Supabase，可在“设置 -> 账号与云端同步”登录账号，并选择手动或自动同步。

## 补打卡说明

如果晚上 12 点前忘记保存当天打卡，可以第二天补录。

1. 进入“每日打卡”页。
2. 在页面右上方选择要补录的日期。
3. 如果该日期没有任务记录，点击“生成该日任务”。
4. 勾选完成情况，填写实际学习时长、质量和总结。
5. 点击“保存打卡”。

保存补打卡后，系统会：

- 保留该日期的完整历史记录。
- 根据该日期完成情况生成学习建议。
- 从未完成任务、备注和总结中沉淀薄弱点。
- 如果是该日期第一次保存，会更新整体进度。

注意：保存补打卡后，首页策略和统计会基于最新历史记录重新计算。如果今天的任务只是系统刚生成、还没有勾选或手动编辑，系统会自动按新的历史表现刷新今天的任务概览；如果你已经改过或保存过今天任务，系统会保留你的手动安排，不会强行覆盖。

## 手机使用

如果只在电脑本地运行，手机通常无法直接访问 `localhost`。推荐部署到 Vercel、Netlify、Cloudflare Pages 或自己的服务器。

部署到 HTTPS 地址后：

1. 用手机浏览器打开网站地址。
2. iPhone Safari：点击分享按钮，选择“添加到主屏幕”。
3. Android Chrome/Edge：打开菜单，选择“安装应用”或“添加到主屏幕”。
4. 添加后可像普通 App 一样从桌面打开。

PWA 只是让网站更像 App。数据是否跨设备同步，取决于是否启用 Supabase 云同步。

## 迁移到手机

### 方案一：导出备份后导入手机

这是最快的方式，不需要账号和云端。

1. 在电脑打开网站。
2. 进入“设置”。
3. 点击“导出备份”，得到一个 `.json` 文件。
4. 把 JSON 文件发到手机，例如微信文件传输助手、邮箱、OneDrive、坚果云、百度网盘或数据线。
5. 用手机浏览器打开同一个网站地址。
6. 进入“设置”。
7. 点击“导入备份”，选择刚才的 JSON 文件。
8. 手机会恢复电脑端的打卡记录、进度、薄弱点和设置。

注意：这种方式是手动迁移。迁移后电脑和手机不会自动保持一致，需要你定期导出和导入。

如果手机打开网站显示“网页连接失败”，通常是因为打开了电脑端的 `localhost` 或 `127.0.0.1`。手机上的 `localhost` 指手机自己，不是电脑。

本地局域网访问步骤：

1. 电脑和手机连接同一个 Wi-Fi。
2. 双击 `一键启动.bat`。
3. 启动窗口会显示 `Phone URL candidates`，形如：

```text
http://192.168.1.23:5173
```

4. 在手机浏览器输入这个 `http://电脑IPv4:5173` 地址。
5. 如果 Windows 防火墙弹出 Node.js 访问权限，允许“专用网络/Private networks”。

如果窗口没有显示手机地址，可以在电脑命令行运行 `ipconfig`，找到当前 Wi-Fi 的 IPv4 地址，然后在手机打开：

```text
http://你的IPv4地址:5173
```

### 方案二：部署成手机可访问的网站

电脑本地地址 `http://localhost:5173` 只能电脑自己访问。手机长期使用建议部署到公网 HTTPS 地址。

项目已经内置：

- `vercel.json`：Vercel 部署配置
- `netlify.toml`：Netlify 部署配置
- PWA 文件：`manifest.webmanifest`、`service-worker.js`

推荐 Vercel：

1. 把项目上传到 GitHub。
2. 登录 [Vercel](https://vercel.com/)。
3. 导入这个 GitHub 项目。
4. Framework Preset 选择 `Vite`。
5. Build Command 设置为：

```bash
npm run build
```

6. Output Directory 设置为：

```text
dist
```

7. 部署完成后，Vercel 会提供一个 HTTPS 网址。
8. 手机浏览器打开这个网址。
9. iPhone Safari 选择“分享 -> 添加到主屏幕”；Android Chrome/Edge 选择“安装应用”或“添加到主屏幕”。

注意：只部署网站不会自动同步数据。每台设备仍然各自使用自己的 IndexedDB，除非启用 Supabase 云同步。

### 方案三：Supabase 云同步

如果希望电脑和手机自动同步进度，使用 Supabase。

1. 在 Supabase 创建项目。
2. 打开 Supabase SQL Editor，运行项目根目录中的：

```text
supabase-schema.sql
```

3. 在项目根目录创建 `.env.local`，填入：

```env
VITE_SUPABASE_URL=你的 Supabase Project URL
VITE_SUPABASE_ANON_KEY=你的 Supabase anon public key
```

4. 重启网站。
5. 电脑端进入“设置 -> 账号与云端同步”。
6. 注册或登录账号。
7. 点击“上传本地到云端”。
8. 手机端打开同一个网站，登录同一账号。
9. 点击“从云端拉取”。
10. 确认数据正常后，可以开启“自动同步到云端”。

注意：只使用 `anon public key`，不要把 Supabase 的 `service_role key` 放进前端项目。即使 Supabase 不可用，本系统仍会先保存到本地 IndexedDB。

### 推荐顺序

1. 先用“方案一”把当前数据迁移到手机，马上可用。
2. 再用“方案二”部署成手机可访问的 PWA。
3. 最后用“方案三”开启电脑和手机自动同步。

## Supabase 云同步

云同步是可选功能。本系统采用“本地优先”策略：

- 每次修改都会先保存到本机 `IndexedDB`。
- Supabase 同步失败、额度用完、网络断开或登录过期，都不会影响本地继续打卡。
- 云端同步只是额外备份和跨设备同步层。
- 设置页会显示最近上传、最近拉取和云端错误。

### 1. 创建 Supabase 项目

在 Supabase 新建项目后，进入 SQL Editor，执行项目根目录的：

```text
supabase-schema.sql
```

该 SQL 会创建 `study_snapshots` 表，并开启 RLS，只允许用户读取和修改自己的学习快照。

### 2. 配置环境变量

复制 `.env.example` 为 `.env.local`：

```bash
copy .env.example .env.local
```

填入 Supabase 项目的 URL 和 anon key：

```env
VITE_SUPABASE_URL=https://your-project-ref.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-key
```

然后重启网站。

### 3. 登录与同步

进入“设置 -> 账号与云端同步”：

- 注册或登录邮箱账号。
- 点击“上传本地到云端”，把当前浏览器数据备份到 Supabase。
- 在另一台设备登录同一账号后，点击“从云端拉取”。
- 确认数据正常后，可以开启“自动同步到云端”。

建议第一次在新设备拉取前，先导出一份本地 JSON 备份。

## 数据说明

当前版本的数据策略：

- 主存储：浏览器 `IndexedDB`，比 `localStorage` 更适合长期保存结构化数据。
- 兼容迁移：如果浏览器里已有旧版 `localStorage` 数据，系统会自动迁移到 `IndexedDB`。
- 手动备份：设置页可以导出完整 JSON 备份，文件名包含导出日期。
- 恢复数据：设置页可以导入本系统导出的 JSON 文件，导入后会覆盖当前浏览器中的应用数据。

当前已经支持可选账号云同步。后续还可以扩展为：

- 日历视图
- 更细的章节题量统计
- 更精细的多设备冲突合并
- 真正的原生移动端 App
